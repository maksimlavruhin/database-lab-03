# Лабораторная работа №3 · Подзапросы, типы и выражения

Настольное приложение для учёта экспериментов по ИИ-модерации текста. В этой версии доступны функции предыдущих лабораторных.

## Запуск

Скачайте или клонируйте репозиторий и откройте его папку в терминале.

Нужны Python 3.12, запущенный PostgreSQL версии 13 или выше и роль с правом создавать схемы в выбранной базе. Для чистого запуска подойдёт локальная база `postgres` или отдельная учебная база. Дистрибутивы для macOS, Windows и Linux доступны на [сайте PostgreSQL](https://www.postgresql.org/download/).

**macOS и Linux**

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m lab03
```

**Windows PowerShell**

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m lab03
```

В окне приложения введите адрес, порт, имя базы, имя роли PostgreSQL и пароль. Адрес `localhost` и порт `5432` подходят для локального PostgreSQL со стандартными настройками.

1. Нажмите **Подключиться**.
2. Нажмите **Создать схему и таблицы**.
3. Нажмите **Добавить демонстрационные данные**.
4. Откройте **Показать данные** и выберите инструмент работы.

Приложение использует схему `moderation_lab3`. При стандартной структуре создание схемы и загрузку примеров можно повторять. Меняйте структуру в выбранной лабораторной. Если переименуете базовые таблицы или поля, верните исходные имена для дальнейшего использования сводки и готовых форм ввода.

Конструкторы выводят до 1000 строк. Загруженные результаты можно сортировать по заголовкам столбцов и фильтровать по тексту. Пароль вводится при подключении. События и ошибки записываются в `database-labs.log`.

## Возможности

- [Формы подзапросов и выражений](database_labs/query_forms.py) поддерживают ANY, ALL, EXISTS, корреляцию по ключам, SIMILAR TO и NOT SIMILAR TO, CASE с несколькими WHEN, COALESCE и NULLIF. SELECT содержит COUNT, SUM, AVG, MIN, MAX, GROUP BY и HAVING.
- [Модуль типов](database_labs/structure_forms.py) создаёт ENUM и составные типы, показывает определения и позволяет переименовывать или удалять типы, дополнять ENUM и использовать типы в новых таблицах.

## Что показать на защите

1. Откройте подзапросы. Для EXISTS выберите `datasets` снаружи и `experiments` внутри. Включите корреляцию `datasets.id = experiments.dataset_id`. После загрузки примеров получите два датасета с экспериментами.
2. Для некоррелированного ANY сравните `experiments.f1` через `>` с `experiments.f1` внутреннего запроса. При ANY вернутся пять запусков, при ALL — ни одного.
3. В поиске по `experiments.title` попробуйте SIMILAR TO с шаблоном `Блог:%`. Получите три записи. NOT SIMILAR TO выдаст остальные три.
4. В CASE добавьте правило `f1 >= 0.85` → **Высокий**, затем `f1 >= 0.75` → **Средний**. В поле ELSE введите **Базовый**. Для `notes` проверьте COALESCE со значением **Без заметки**, затем NULLIF со значением **После очистки текста**.
5. Создайте ENUM `review_state` с метками `draft, approved` и составной тип `score_info` с полями `f1` (numeric) и `comment` (text). Создайте таблицу `reviews` с полями `state` типа `review_state` и `details` типа `score_info`.
